    Add a missing key to an identity

    An identity's keys are not fixed at creation. If one of the five is missing — say the CRITICAL authentication key, without which tokens cannot be moved — it can be added later. This is the one transition the MASTER key signs, and it is what that key is for.

    It only goes one way. A CRITICAL authentication key, the master key and the transfer key can never be disabled once they are on an identity, so the one you add is the one you keep. And without the master key none of this is possible at all.

    Bind this key to one contract

    A key normally works with every contract. Binding it to one means it works only there, and some contracts insist on that: DashPay's contact requests set requiresIdentityEncryptionBoundedKey and requiresIdentityDecryptionBoundedKey, so the keys that encrypt a contact request have to be bound to DashPay. A key that cannot be used anywhere else also cannot be replayed anywhere else, which is the reason to want it.

    Most keys want no bound at all — a DashPay profile needs none, and neither does anything to do with tokens. If you are unsure, leave this closed: a bound key is useless for everything it is not bound to, and it can never be unbound.
